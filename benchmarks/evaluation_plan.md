# Model and benchmark evaluation plan

The system target is repeated prefill after main KV eviction. A benchmark's ordinary single-request accuracy does not by itself exercise this cache lifecycle. Use the same tokenized causal prefix for capture and replay; new suffix queries must run their own selector.

## Research basis

| Work | Venue | Relevant evaluation and scope |
|---|---|---|
| [Quest](https://github.com/mit-han-lab/quest) | ICML 2024 | Passkey, LongBench tasks and PG-19. Its reported LongBench protocol includes full-attention document prefill; do not present that protocol as proof of sparse prefill quality. |
| [MInference](https://proceedings.neurips.cc/paper_files/paper/2024/hash/5dfbe6f5671e82c76841ba687a8a9ecb-Abstract-Conference.html) | NeurIPS 2024 | RULER, InfiniteBench, PG-19 and needle retrieval inform long-context prefill quality/performance checks. |
| [CacheBlend](https://www.microsoft.com/en-us/research/wp-content/uploads/2024/09/eurosys25-final999.pdf) | EuroSys 2025 | Multi-document QA and summarization, TTFT and throughput; useful for overlap methodology, although it caches KV rather than selector outputs. |
| [Squeezed Attention](https://aclanthology.org/2025.acl-long.1568/) | ACL 2025 | LongBench, RULER and shared-document questions. Its repository lists PreFixQA tooling as roadmap; no claim of reproducing that benchmark is made here. |

## Models

- **MiniCPM-SALA 9B**: a pretrained native sparse/linear model. The [official config](https://huggingface.co/openbmb/MiniCPM-SALA/blob/main/config.json) has `dense_len=8192`, block size 64, sparse top-k 64 and local window 2048. Verify actual native selector calls above 8K; an 8K run alone cannot establish sparse replay behavior. Existing SGLang support and native kernels must be checked on the tested GPU.
- **Qwen3-4B**: an available pretrained dense model for framework/task sanity baselines. It is not evidence for selection-cache speedup or for native sparse quality.
- **GLM-5.3-0.6B-A0.4B**: a tiny DSA architectural checkpoint, [described by its publisher](https://huggingface.co/inference-optimization/GLM-5.3-0.6B-A0.4B) as randomly initialized then toy-text fine-tuned. Use only for adapter mechanics; never use its benchmark scores as representative task quality.

## Tiny quality subsets

Use pinned official templates, data and scoring; publish sample IDs, actual token counts, truncation flags and predictions/scores, not the long source documents. These small runs are smoke subsets, not full leaderboard results.

| Benchmark | Tasks | Initial subset | Metrics |
|---|---|---|---|
| [LongBench v1](https://aclanthology.org/2024.acl-long.172/) | `passage_retrieval_en`, `2wikimqa` | 4–8 fixed examples per task; 8K/16K caps | Official retrieval score / QA token F1 |
| [RULER](https://openreview.net/forum?id=kIoBbc76Sy) | `niah_single_1`, `niah_multikey_2` | 4–8 generated examples per task and length | Official string-match retrieval scoring |

RULER data must be generated by the pinned official scripts, not a hand-written similar needle task. LongBench context caps are not guaranteed actual input lengths; inspect token counts. If truncation removes answer evidence, compare replay against the native baseline on the exact same truncated input. Greedy generation and the same output budget should be used for all replay variants.

## Cache-specific workload

For 2–4 selected inputs, compare native cold prefill, complete KV hit when supported, full selection replay, and head recomputation fractions 1/8, 1/4 and 1/2. Disable or flush ordinary prefix KV caching for selection-replay measurements. Check actual selector calls and row counts, including short prefixes, before claiming a hit. Keep the learned model's own selector and attention; changing top-k or installing a different sparsifier changes the algorithm.

Separate first-time capture/encoding from repeated hits. Report full request TTFT or explicitly named first-token wall time, P50/P95 with raw samples, CPU payload and metadata bytes, temporary GPU buffers, startup waits and throughput. First-token wall time includes runtime overhead and should not be relabeled pure GPU prefill. For offline calls that generate multiple tokens, total call duration is not TTFT.

First compare native-vs-native repeat variability, then native-vs-replay selected sets, order/padding, logits and generated tokens. A model answering incorrectly in both modes can still demonstrate faithful replay, but does not establish task quality. Changed floating-point reduction order or nondeterministic native selection must be reported rather than silently weakening an exactness assertion.

Status and executed results belong in the corresponding run reports. A listed model, task or adapter is a planned validation target until its run artifacts demonstrate completion.
